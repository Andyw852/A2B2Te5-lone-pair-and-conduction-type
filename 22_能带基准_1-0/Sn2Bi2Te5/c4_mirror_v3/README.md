# Sn₂Bi₂Te₅ · c4_mirror_v3：避开 FOCK_FCC 判据边界的镜面网格（HSE06+SOC，NKRED 2 2 1 不变）

2026-10-29。目的与 [`../c4_mirror/README.md`](../c4_mirror/README.md) 相同：在镜面内找价带的真实极大、导带的真实极小。INCAR、KPOINTS 与 c4_mirror、c3_valley 逐字相同（`NKRED 2 2 1`，`KPOINTS_OPT_NKBATCH = 36`），**只把网格步长从 0.025 改成 1/36**。

## 崩溃的根因

以下依据 VASP 6.6.0 源码（集群侧读出）：

- `fock_dbl.F:1407` 要求 `NQ_USED × NKREDX × NKREDY × NKREDZ = 288`，即 `NQ_USED = 72`。
- `NQ_USED` 的算法：对每个 KPOINTS_OPT 点 k，在自洽全网格的 288 个点上算 q = k_full − k，然后用 `SKIP_THIS_KPOINT_IN_FOCK` 筛掉一部分：
  - 判据是 `MOD(FLOOR((q+32)·12 + 0.5), 2) ≠ 0`（x、y 方向）；
  - z 方向 NKREDZ = 1，不筛。

**为什么平时恰好是 72**：每个方向上，12 个网格坐标减去 k 再乘 12，是 12 个间隔为 1 的数。FLOOR 之后模 2，恰好留下一半，**与 k 取什么值无关**。

**唯一的例外**：12·k 恰为半整数，即 k 的 x 或 y 分数坐标是奇数/24。这时 12 个数全都正好落在整数上，FLOOR 取哪一边由浮点舍入决定，留下的个数就不再是一半，于是 `NQ_USED ≠ 72`。

**原网格**步长 0.025，其中 u = −0.125、−0.375 两列（12u = −1.5、−4.5）正是这种点；三重旋转表示 (−u,u,w)、(0,−u,w) 也一样。把已知的批逐一对照：

| 批 | 奇数/24 点 | 结果 |
|---|---:|---|
| c2 六批、c3 | 0 | 全部通过 |
| c4 原版第 1 批（u = 0 … −0.075） | 0 | 通过 |
| c4 原版第 2 批（含 u = −0.125）；单独跑；NKREDY = 1 | 12 | 崩溃（68/72；138/144） |
| c4 第二版第 1 批 | 0 | 通过 |
| c4 第二版第 2 批（含 u = −0.125） | 10 | 崩溃 |
| 按 w 分组的每一批（每批都含全部 u） | 4 | 未提交，应会崩溃 |

“kz 取值数”“Γ–A 线点数”“批内有无 ±k 点对”都只是碰巧与此相关。

**模拟验证**：照上述判据，在全网格坐标上加 10⁻¹⁴ 量级的舍入噪声：
- u = −0.125 的点，`NQ_USED` 在 57–95 之间乱跳，包括实测的 68；NKREDY = 1 时在 120–168 之间乱跳，包括实测的 138；
- 其他点始终是 72。

**结论**：NKRED 2 2 1 可以用，不必改成 1 1 1；不要放分数坐标为奇数/24 的点就行。`c4_mirror_scan.py` 的 `write_kpoints` 现在遇到这种点直接报错，c4 和 c5 都受这道检查保护。

## 网格

由下面的命令生成：

```
python 10_脚本/c4_mirror_scan.py grid Sn2Bi2Te5 --out 22_能带基准_1-0/Sn2Bi2Te5/c4_mirror_v3 --du 1/36 --umin=-15/36 --split
```

- **u**：0 到 −15/36（−0.417），步长 1/36（0.0457 Å⁻¹），16 列。
  - 12u = −k/3，离半整数至少 1/6，远离判据边界；
  - 含 u = −1/6、−1/3，即 c2 路径上 #11、#119 两个谷所在的 u。
- **w**：12 个，与原来相同。
- **点数**：16 × 12 = 192 个网格点，加 6 个锚点（每批 1 个）、1 个 c2 校验点（#101）、4 个对称校验点，共 203 点，分 6 批。
- **排法与原版相同**：每批 kz 取 12 个值，第 2–6 批在 Γ–A 线上几乎没有点。所以第 2 批顺带检验了根因：
  - 它能通过，说明“kz 取值数”的猜测不成立；
  - 它若崩溃，就说明还有别的原因。
- **文件**：
  - `KPOINTS_OPT`：6 批合在一起，单个作业顺序跑全部批时用；
  - `KPOINTS_OPT_b01`…`_b06`：逐批作业用；
  - `c4_grid.json`：每个点的全局序号。**不要手改 KPOINTS_OPT。**

## 计算：建议每批一个作业，6 个并行

| 项 | 内容 |
|---|---|
| 目录 | 集群上建 `c4_mirror_v3/b01` … `b06` |
| INCAR、KPOINTS | 本目录的。**NKRED 不要改** |
| POSCAR、POTCAR | 与 c_hse_A、c3_valley 相同 |
| WAVECAR | 从已收敛的 `c_hse_A/WAVECAR` 给每个目录各复制一份，不要用 PBE 的 |
| KPOINTS_OPT | `bNN` 里放 `KPOINTS_OPT_bNN`，改名为 `KPOINTS_OPT` |
| 资源 | 64 核快节点，`--time=0-12:00:00`，后台 `sleep 41400` 后写 `LABORT = .TRUE.` |

**为什么逐批**：墙钟约 6–7 小时，顺序跑约 1.5 天；某一批出问题只影响这一批。也可以用合在一起的 `KPOINTS_OPT` 单个作业顺序跑，此时 `--time=3-00:00:00`，分析时去掉 `--parts`。

**每个作业的检查**
1. **自洽**：从 c_hse_A 的波函数起步，几步内收敛，energy(sigma->0) 与 c_hse_A 相差 < 1 meV。
2. **批开始后**：`k-point batch` 一行之后出现 DAV 迭代。出现 `internal error` 就贴报错原文和批号，这个作业停下，其余继续。
3. **结尾**：`General timing` 与 `aborting loop because EDIFF is reached` 都要有。

**要推送的输出**（每个 `bNN/`）：`PROCAR_OPT.gz`（必须）、`OSZICAR`、`out.log` 中从 `k-point batch` 开始的部分。

## 分析

```bash
python 10_脚本/c4_mirror_scan.py analyze 22_能带基准_1-0/Sn2Bi2Te5/c4_mirror_v3 \
  --parts 22_能带基准_1-0/Sn2Bi2Te5/c4_mirror_v3/b0{1,2,3,4,5,6} --split \
  | tee 22_能带基准_1-0/Sn2Bi2Te5/c4_mirror_v3/analyze.log
```

- **验收**（开头两行）：
  - 7 个校验点与 c2 路径的最大差 < 0.5 meV（口径与 c2、c3 相同）；
  - 对称校验 < 0.1 meV。

  任一不满足就停下汇报。价带第一行注明“在 umin 边界上”也停下汇报。
- **通过后**：脚本写出 `c4_extrema.json`，并在 `../c5_star/` 写出 c5 的 `KPOINTS_OPT` 与 `KPOINTS_OPT_b01`…（同样经过奇数/24 检查）。c5 设置同上，逐批或单个作业都可以，直接提交，不用等 Claude。
- **c5 的拟合**：`python 10_脚本/c4_mirror_scan.py fit 22_能带基准_1-0/Sn2Bi2Te5/c5_star --parts <c5 各批目录>`。

`--parts`、`--split` 已用合成数据测过：
- 构造满足 D3d 对称的合成能带；
- 逐批读入与单个 PROCAR_OPT 的结果逐字节相同；
- 少一批会报错；
- 能找到合成能带的极值，c5 能还原其质量。
